# PCuino AppSDK

PCuino uses a drop-in application model for Arduino. The operating system provides the core API; applications self-register through `AppRegistrar`.

## Project layout

```text
PCuino/
├── PCuino.ino
├── config.h
├── core_api.h
├── README.md
├── src/
│   └── apps/
│       ├── chat/
│       │   └── app.cpp
│       ├── ftp/
│       │   └── app.cpp
│       ├── viewer/
│       │   └── app.cpp
│       └── <your-app>/
│           └── app.cpp
└── toolkit/
    └── PCuino_AppSDK.html
```

## Recommended Terminal Software

The **Audio FTP OS** relies on ANSI escape sequences for its interactive shell, status bars, progress indicators, and color-coded output. For the best experience, we recommend using **Tera Term** (for Windows) or any fully ANSI-compliant serial terminal emulator.

### Recommended Tera Term Settings

To ensure proper rendering of colors, screen clearing, and line endings, configure your terminal with the following settings:

1. **Serial Port Connection:**
   * **Baud Rate:** `115200` (or match your Arduino sketch `Serial.begin()` rate)
   * **Data:** `8-bit`
   * **Parity:** `None`
   * **Stop Bit:** `1-bit`
   * **Flow Control:** `None`

2. **Terminal Setup (`Setup` -> `Terminal`):**
   * **Terminal size:** Columns: `80`, Rows: `24` (or standard window size)
   * **New-line:** 
     * Receive: `AUTO` (or `CR+LF`)
     * Transmit: `CR` or `CR+LF`
   * **Local echo:** `Off` (let the device handle command echoing)
   * **ANSI color:** Ensure ANSI color support is enabled so status prompts and progress bars display correctly.

3. **Keyboard & Display:**
   * Enable **Backspace key** to send `DEL` (`0x7F`) or `BS` as required by your input buffer handling.

## Creating an app

Use **PCuino AppSDK** to build the app visually. The SDK generates exactly one source file:

```text
app.cpp
```

Put it in:

```text
src/apps/<name>/app.cpp
```

Because the Arduino build compiles source files under `src/apps/`, no central app list needs to be edited.

## App registration

Every app defines its `AppHooks` and creates a static registrar:

```cpp
static const AppRegistrar myapp_auto_register(&myapp_hooks);
```

The presence of the app's `.cpp` is its installation switch.

There is intentionally **no**:

- `APP_CHAT`, `APP_FTP`, `APP_VIEWER`, or other app-selection flag
- `register_all_apps()`
- `apps_bundle.cpp`
- central application list
- generated `app.h`
- manual registration step

## Core API location

`core_api.h` is at the **project root**. An app generated by AppSDK therefore includes it with:

```cpp
#include "../../../core_api.h"
```

from `src/apps/<name>/app.cpp`.

## AppSDK block model

Event blocks are the top-level handlers:

- When App Opens
- When User Enters Line
- When Message Received
- When Send Finishes
- When Disconnected

Actions are placed inside an event. Logic blocks such as **If Online** and **If Message Equals** can contain further actions. AppSDK preserves this nesting when generating C++ instead of flattening all actions into every event.

`If Message Equals` is intended for the **Message Received** event because it tests the received `data` buffer.

## Built-in applications

The clean build includes:

- **Chat** — application messaging UI
- **FTP** — file transfer/filesystem UI
- **Viewer** — file viewing UI

Additional apps can be added by dropping their generated folder into `src/apps/`.

## App IDs

Each app has a one-character printable Wire/App ID. IDs must be unique among installed applications and may not be `:`.

## Updating an existing app

Apps created with an older App Maker may contain `app.h`, `*_register()`, `APP_*` flags, or an old `core_api.h` include. Regenerate the app with the current **PCuino AppSDK** and replace its `app.cpp`. The current SDK generates only `app.cpp`, uses `../../../core_api.h`, and self-registers with `AppRegistrar`.

## Removing an app

Delete its app folder from `src/apps/`. No core source or configuration file needs to be changed.

## Important Arduino note

Do not keep obsolete copies of `apps_bundle.cpp`, old `app_*.h` files, or legacy `APP_*`-controlled apps in the sketch tree. Arduino may compile `.cpp` files that remain in the project, even if they are not part of the intended architecture.
### Import / decompile an existing app

The PCuino AppSDK can import an existing `app.cpp` with **Import app.cpp**. It recognizes AppSDK-generated event/action/logic patterns and reconstructs them as blocks. C++ that has no direct AppSDK block is preserved as a **Custom C++** block rather than being discarded. Global declarations needed by an imported app are preserved as **Custom Global C++**.

This supports inspecting built-in or hand-written apps such as Viewer without pretending unsupported C++ is equivalent to a native block. AppSDK-generated apps can therefore round-trip between blocks and `app.cpp` much more closely.
